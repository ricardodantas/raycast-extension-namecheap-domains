# Codebase Overview

_Generated by the learn-codebase skill on 2026-09-11 at commit `65e58e0`._

## Summary

A Raycast extension that puts a Namecheap account a keystroke away: list the domains you own and open their management pages, check whether a name is free with registration pricing, and verify a name before continuing to Namecheap checkout. It talks to Namecheap's legacy XML API with the user's own API key. Purchases always finish in the browser, so the extension never spends the account balance.

## Tech stack

- **Languages:** TypeScript, TSX (React 19)
- **Frameworks / runtime:** Raycast extension API (`@raycast/api` 2.x, `@raycast/utils` 2.x), Node 22+
- **Build / package manager:** npm, driven by the Raycast CLI (`ray`). npm only: `ray validate` fails if a `pnpm-lock.yaml` or `yarn.lock` is present
- **External services:** Namecheap XML API (`api.namecheap.com`, `api.sandbox.namecheap.com`); `api.ipify.org` with `checkip.amazonaws.com` as fallback for public-IP detection
- **Parsing:** `fast-xml-parser`
- **Skills applied:** `learn-codebase`, `writing-for-agents` (agent docs), `codebase-design` (module boundaries)

## Architecture

The codebase is split by whether a module may touch Raycast. Everything below the line runs in plain Node, which is what makes the unit tests and the smoke script possible without the Raycast app.

    [command views]  list-domains · check-availability · register-domain
           |
        [hooks] ── [errors] ── [setup] ──┐
           |                             |
     [preferences] ────────────────── [storage]        ← Raycast APIs enter here
    ─────────────────────────────────────────────────
     [namecheap/client] ── [namecheap/parse] ── [namecheap/parse-hints]
     [namecheap/ip]        [namecheap/urls]    [namecheap/types]
     [domain/normalize]    [domain/price]                ← Raycast-free

Only two files perform network calls: `src/namecheap/client.ts` (the API) and `src/namecheap/ip.ts` (public-IP echo services).

## Key modules

| Path | Responsibility |
| --- | --- |
| `src/namecheap/client.ts` | Builds and sends API requests (POST by default), chunks availability checks at 50, walks `getList` pages at 100 |
| `src/namecheap/parse.ts` | XML envelope to typed results; raises `NamecheapApiError` carrying number, hint, rejected IP and environment |
| `src/namecheap/parse-hints.ts` | Error number to remediation text, built from observed responses rather than Namecheap's published table |
| `src/namecheap/ip.ts` | Detects the caller's public IPv4 |
| `src/namecheap/urls.ts` | Namecheap web URLs, with the API-access and whitelist pages environment-aware |
| `src/domain/normalize.ts` | Input to candidate domains: scheme stripping, punycode, keyword expansion across default TLDs |
| `src/domain/price.ts` | Chooses and formats the price for a domain, premium included |
| `src/storage.ts` | Splits persistence by sensitivity: encrypted LocalStorage for personal data, the plaintext Cache for public pricing |
| `src/preferences.ts` | Preferences to a configured client; resolves and caches the client IP |
| `src/hooks.ts` | `usePromise` wrappers for domains, availability and pricing |
| `src/setup.tsx` | Shared failure and recovery UI, including the whitelist flow |

## Data & control flow

**List Domains.** `useDomains` builds a client from preferences, resolving the client IP from the preference, then encrypted storage, then a live lookup. `listAllDomains` pages through `domains.getList` and writes an encrypted snapshot. On failure the snapshot is read back and rendered under a banner that names the address to whitelist, taken from Namecheap's error rather than local detection.

**Check Domain Availability.** Typing is debounced, then `buildCandidates` turns the query into either one domain or the keyword across the configured TLDs, capped at 50. `checkDomains` batches those into one call; pricing is fetched separately and cached for a day. Results are never written to disk.

**Register Domain.** The form verifies the name through `domains.check`, shows a confirmation carrying the price, then opens Namecheap's public registration URL. No purchase endpoint is ever called.

## Entry points

The manifest's three `view` commands, each a default-exported React component:

- `src/list-domains.tsx`
- `src/check-availability.tsx` (command preference `defaultTlds`)
- `src/register-domain.tsx` (optional `domain` argument)

`scripts/smoke.ts` is a separate Node entry point that exercises the API without Raycast.

## Build, run, and test

    npm install
    npm run dev        # loads into Raycast (needs the Raycast app)
    npm test           # node --test over tests/*.test.ts via tsx
    npm run typecheck  # tsc over src, tests and scripts
    npm run lint       # ray lint: manifest, icons, ESLint and Prettier
    npm run build      # ray build, includes a type check
    npx ray validate   # everything the store checks

There is no CI configuration in the repo.

## Conventions

- **Raycast-free core.** No `@raycast/api` import reaches `src/namecheap/` or `src/domain/`.
- **Injectable fetch.** `createClient(config, fetchImpl)` takes the fetch implementation, which is how the client is tested without network access.
- **Errors carry remediation.** `NamecheapApiError` exposes the number, environment, rejected IP and a hint; UI reads those fields rather than matching on message text.
- **Storage by sensitivity.** Personal data goes to encrypted LocalStorage; only public reference data goes to the Cache.
- **Tests use the real wire shape.** Fixtures are copied from live responses, not from documentation examples, after documentation samples produced two silent pricing bugs.
- **Formatting** is Prettier at 120 columns, run as part of `ray lint`.

## Risks & rough edges

- **No `metadata/` screenshots**, which a store submission needs.
- **Sandbox mode uses production web URLs.** `registrationUrl`, `managementUrl`, `advancedDnsUrl` and `whoisUrl` in `src/namecheap/urls.ts` are hardcoded to production, so sandbox users see real Namecheap pages for fictional domains. Only the API-access and whitelist URLs follow the preference.
- **ICANN and EAP fees are parsed and never displayed.** `icannFee` and `eapFee` reach `DomainCheckResult` but no view reads them, so a quoted price can sit below the real charge.
- **Command naming overlaps a published extension.** The store's existing `namecheap` extension declares a command with the same title and subtitle as `list-domains`.
- **`Clear Stored Data` is absent from Register Domain**, so the action is reachable from two of the three commands.
- **No CI.** Lint, tests and type checks run only locally.

## Glossary / where to look next

- **Whitelist / client IP** — Namecheap authorises the connection's source address, not the `ClientIp` parameter. Start at [`docs/namecheap-api.md`](namecheap-api.md), then `src/namecheap/parse-hints.ts`.
- **Environment** — sandbox and production are separate accounts with separate keys and whitelists. See `ENDPOINTS` in `src/namecheap/client.ts`.
- **Candidate** — a domain derived from what the user typed. See `buildCandidates` in `src/domain/normalize.ts`.
- **Snapshot** — the last domain list that loaded, kept encrypted for offline display. See `src/storage.ts`.
